01 / 现状诊断

功能很强，
但界面还不太会照顾人。

现有界面把几乎所有信息都摊在一个平面上：一行服务里塞进 9 类信息、最多 6 个动作，正文最小只有 10px。 对熟练用户，它像一张高密度仪表盘；对每天打开它的你，它更像一份需要“读”的报表，而不是一间可以“待”的小屋。

P001

一行装下所有，眼睛没有落脚点

服务行同时承载名称、状态、分组、端口、命令预览、PID、CPU、内存、运行时长与最多 6 个按钮；大量正文使用 text-[10px] / text-[11px]。

影响：扫读慢、误点率高改法：卡片 + 抽屉分层
P002

危险动作没有护栏

删除是常驻的 ✕，点击立即执行；“全部停止”就贴在“全部启动”旁边；停止与删除都没有确认或撤销。

影响：一次误触就中断服务改法：收进菜单 + 确认 + 撤销
P103

状态淹没在颜色里

类型色、状态色、强调色同时争抢注意力；“运行中 / 启动异常 / 已停止”缺少全局聚合入口，异常不会主动浮到眼前。

影响：故障发现滞后改法：状态三件套 + 健康入口
P104

反馈只够“看见”，不够“放心”

启停与批处理只靠 3.2 秒 toast；按钮没有进行中状态；1 秒轮询没有最后更新时间；失败后也没有下一步。

影响：不确定、重复点击改法：操作三态 + 可追踪错误
P105

日志和服务是“异地恋”

实时控制台固定在底部，只跟随当前选中项；224px 高度一次只能看五六行，筛选、编码、清屏全挤在 36px 的工具栏里。

影响：排障时来回切换改法：日志进入服务详情
P206

第一次打开，没有人带路

没有服务时是纯空白列表；启动失败只显示“启动异常”；添加表单把 10 多个工程化配置项一次铺开，也没有路径选择。

影响：冷启动放弃、表单出错改法：空态引导 + 表单分层

02 / 设计原则

可爱是外壳，
顺手才是骨头。

萌系不是把界面刷成粉色，而是让每一次交互都更轻柔、更有回应。以下六条原则贯穿全部界面： 任何装饰都不能以牺牲可读性、可预测性和可恢复性为代价。

01

一眼看懂

状态同时用颜色、图标和文字表达；每个服务只有一个主行动，数字按“现在是否正常”排序，而不是按数据库字段排序。

Glanceable
02

一层一层来

列表负责扫读，抽屉负责深潜，设置负责个性化。常驻界面只保留决定“下一步做什么”所需的信息。

Progressive disclosure
03

每个动作都有回应

按下 100ms 内有反馈，执行中有进行中状态，结束后有成功/失败结果；失败必须带上“为什么”和“下一步”。

Responsive
04

允许反悔

停止、删除、批量操作都有确认或撤销；表单改动未保存时离开会提醒；错误可以用一次点击回到正常。

Forgiving
05

说人话

“可执行程序 / 解释器路径”改成“启动程序”；“端口未监听”后面直接给“重启服务 / 查看日志”。术语留给高级设置。

Plain language
06

萌度可调

装饰强度三档、樱昼/樱夜双主题、动效跟随系统。可爱是默认款，不是强制款；克制模式同样完整好用。

Adjustable

“我希望你打开它的时候，先松一口气，再开始动手。”

03 / 视觉语言

奶油、樱粉、鲸蓝，
和一点点电气感。

视觉方向叫「Sugar Star」：以奶油白为底、樱粉为主色，紫藤与薄荷为辅色，鲸蓝作为角色冷色锚点； 用大圆角、贴纸式标签和蓝鲸女仆头像，保留 FlashManager 原本的“速度与电气”隐喻，但把霓虹换成了软糖。

ANNOTATIONS

六个设计决策，落在这些位置

01全局命令入口

用 Ctrl+K 收拢“搜索 + 操作”，顶栏不必排满 5 个批量按钮。

02萌度可调

审美是偏好，不是强制；三档萌度随时切换，克制模式保留全部功能。

03健康聚合

异常主动浮到侧栏与主区顶部，不再等用户逐行扫描状态标签。

04指标扫读

四张卡只回答“现在好不好”，细节趋势留给详情抽屉。

05单主行动

每张服务卡只有一个主按钮，打开、日志、更多降级为图标。

06状态三件套

颜色 + 图标 + 文案；色弱用户不靠颜色也能分辨运行、停止与异常。

05 / 关键流程

把“能操作”，
变成敢操作。

萌系界面最容易犯的错，是把所有东西都变成圆角和粉色，却让流程更绕。下面四条是这次改版真正要重写的交互链路： 每一条都减少一步决策、增加一层保护，或者把错误变成可执行的下一步。

A启动失败 → 恢复

错误不是终点，是诊断入口

现在

卡片显示“启动异常”，底部 toast 3.2 秒后消失；用户需要自己想到点“诊断”，再读一屏原始字段。

提案

卡片直接展开一行“端口 8741 没有响应”，主按钮变成“重试”，旁边是“去诊断”；诊断页给出三条检查结果和“重启并再测一次”。

可恢复下一步明确状态持久
B批量停止 → 撤销

一次说清楚“会影响谁”

现在

“全部停止”紧挨“全部启动”，点击立即执行；成功与否只有一条 toast。

提案

批量菜单按范围分组并显示数量；停止前列出将受影响的 4 个服务；完成后提供 8 秒撤销，逐个恢复先前的运行状态。

范围预览确认可撤销
C添加服务 → 自动识别

把 12 个字段，变成 3 个决定

现在

打开表单先面对 5 个类型按钮和 10 多个字段，需要理解解释器、工作目录、编码等概念。

提案

优先提供“把文件夹交给小闪”：自动识别 Python/Node/Nginx/EXE，展示识别结果与将执行的命令，确认即可入驻；手动添加则默认收起高级项。

识别优先基础/高级分层可预览
D首次打开 → 三步入驻

空状态也能教人做事

现在

没有服务时列表空白，控制台空白，用户不知道应该先添加还是先启动。

提案

空态给出两个明确入口（添加 / 自动识别）和一句“受管服务是什么”；完成后用一条 checklist 告诉用户下一步可以做什么。

空态引导两个入口可跳过

GUARDRAILS

四条不能破的底线

01字号底线

正文 ≥ 13px，状态与操作 ≥ 11px，说明文字 ≥ 10px；不再用 10px 承载关键信息。

02对比度底线

正文 ≥ 4.5:1，大字 ≥ 3:1；状态色永远搭配图标与文字，暗色主题单独校验。

03可恢复底线

停止 / 删除 / 批量操作必须确认或撤销；删除只移除配置，不删本地文件，并在文案里说清楚。

04降级底线

prefers-reduced-motion 下关闭所有装饰动画；无鼠标也能完成主流程；萌度“克制”模式不丢任何功能。

  • 服务卡片的主行动在 1240 与 980 宽度下都无需滚动即可见
  • 所有停止 / 删除 / 批量操作都有确认或 8 秒撤销
  • 异常状态包含“影响 + 原因 + 下一步”，而不是只有颜色
  • 正文 ≥ 13px、状态与操作 ≥ 11px，关键对比度 ≥ 4.5:1（两套主题各测一次）
  • Ctrl+K、/、N、L、Esc、↑↓、Enter 可完成主流程
  • 空 / 载入 / 异常 / 成功四种状态都有设计稿与实现
  • prefers-reduced-motion 下无装饰性动画
  • 抽屉与弹窗有焦点锁定、Esc 关闭、关闭后焦点归还
  • 日志超过 500 行仍保持滚动流畅，切服务不串日志
  • 萌度“克制”模式隐藏装饰但不隐藏任何信息与操作

取舍与风险

可爱会不会削弱专业感？

默认“标准萌度”，提供“克制”一键降级；颜色只负责语义，装饰不进入数据区。先让老用户试用克制模式。

卡片化会不会降低密度？

1240 下是 2 列 7 张卡，一屏可见约 6 个服务；窗口低于 940px 时降为 1 列。真正的高密度信息放进抽屉，而不是删除。

动效会不会拖慢低端机？

只动 transform 与 opacity；吉祥物动画 1 个合成层；日志与卡片不逐帧重排。

暗色主题维护成本？

只覆盖 20 个 CSS 变量，不写第二套组件；用对比度脚本在 CI 里校验关键组合。

RECOMMENDATION

建议先落“主界面 + 抽屉 + 日志”这一刀。

它同时解决信息过载、上下文割裂和状态扫读三个 P0/P1 问题，而且不碰后端，能在 3–4 天内看到真实可用版本。表单、命令面板和萌度系统可以第二步跟进。
